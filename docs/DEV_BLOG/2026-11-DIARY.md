# Development Diary - November 2026

---

## 2026-11-04: One self-contained `Generals Zero Hour.app` for macOS

Replaced the build/deploy/`run.sh` dance (Homebrew + `~/VulkanSDK` + `~/vcpkg` +
`~/GeneralsX/GeneralsZH`) with one command that produces a double-clickable,
relocatable, ad-hoc-signed app with the retail data inside it. Inspired by the way
seedds/nxnative packs a Switch title into a single `.app`.

```sh
./scripts/build/macos/make-app-zh.sh --game-data <retail Zero Hour folder>
# -> dist/Generals Zero Hour.app
```

What changed:
- **Binary configures itself** (`GeneralsMD/Code/Main/SDL3Main.cpp`,
  `ConfigureMacAppBundleRuntime`). When running from `<App>.app/Contents/MacOS` it
  `chdir`s into `Contents/Resources/GameData` and sets the MoltenVK ICD, DXVK config,
  fontconfig, `DXVK_STATE_CACHE_PATH` and log paths (all `setenv(..., 0)`, so a developer
  environment still wins). Outside a bundle it is a no-op, so `deploy`/`run.sh` still work.
  Launched from Finder, stderr goes to `~/Library/Logs/GeneralsX/GeneralsXZH.log`.
- `dx8wrapper.cpp` loads `@executable_path/../Frameworks/libdxvk_d3d8.0.dylib` first.
- **No Homebrew in the link.** `vcpkg.json` now builds static FFmpeg on macOS (`ios | osx`),
  `cmake/sdl3.cmake` disables SDL3_image's libpng backend on all Apple platforms (stb /
  ImageIO decode PNG, as on iOS), and the `macos-vulkan` preset no longer points
  `PKG_CONFIG_PATH` at `/opt/homebrew`. The bundle went from 25 dylibs to 8.
- `scripts/build/macos/bootstrap-toolchain.sh` installs cmake/ninja/meson (pinned venv),
  vcpkg (full clone at a pinned commit - `vcpkg.json`'s baseline predates the `ffmpeg
  8.1.1#2` override), vulkan-loader + glslang + pkgconf (vcpkg, dynamic triplet
  `cmake/triplets/arm64-osx-dynamic.cmake`) and a checksummed MoltenVK v1.4.1 into the
  git-ignored `.toolchain/`. Only Xcode Command Line Tools are required.
- `scripts/build/macos/package-app-zh.sh` assembles the bundle, rewrites install names
  to `@rpath`, replaces every `LC_RPATH`, **fails if anything still references a path
  outside the bundle**, clones the game data with APFS `cp -c` (no extra disk), and signs
  inside-out. The data exclude list is shared in `scripts/build/common/gamedata-excludes.txt`.
- `Patches/dxvk-macos-libcxx.patch` (applied by `cmake/dx8.cmake`): Xcode 27's libc++
  rejects the empty `std::tuple()` piecewise key in
  `DxvkPipelineManager::createNullFsPipelineLibrary`. Should be upstreamed to the fork.

Gotchas found while verifying:
- fontconfig resolved its cache to `Contents/var/cache` (relative to the executable) and
  silently invalidated the code-signature seal. The packager now rewrites `<cachedir>`
  to `~/Library/Caches/GeneralsX/fontconfig`.
- vcpkg searches upward for `vcpkg.json`; the classic-mode tool install must run from
  a directory outside the repo.

Known gaps:
- **SagePatch is not in the app.** It relies on `DYLD_INSERT_LIBRARIES`, which cannot be
  set from inside the process. Needs a link-time or `dlopen` integration.
- Ad-hoc signed only: first launch needs right-click > Open (or Privacy & Security >
  Open Anyway). The app contains retail data - for personal use, do not distribute it.
- Retail replay determinism check against the old setup is still to be done.
